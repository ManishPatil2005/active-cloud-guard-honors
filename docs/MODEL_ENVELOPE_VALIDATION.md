# Local-model envelope rejection and metadata validation

QA-007 / R4 / R7 / R8, 9 October 2026. First numbered maintenance step toward the owner's production/research-readiness goal. Start revision407a33d0bd28df3cc83c0a4fcecc800b955caabc. No engine rebuild, new stack/model or production deployment.

## Reproduced defect and acceptance

The chat adapter accessed message/content and completion fields before checking their structure. Unexpected roots, missing messages/content or null messages produced KeyError/AttributeError; the exception handler could itself fail while trying to preserve content. Five of six mocked before-cases failed the expected InvalidModelOutput rejection contract; numeric content already produced that superclass rejection. This was a diagnostic/admission defect, not an observed model-server compromise or security-effectiveness failure.

Acceptance: malformed chat envelopes have an owned sanitized rejection, usable string content remains separately available for review, invalid envelopes never enter the audit cache, malformed cached entries trigger actual fresh inference rather than a fabricated clean verdict, completion/inference metrics are not accepted with wrong types, and model/embedding metadata fails explicitly before persistent indexing. Existing valid response/retrieval/grounding/probe/scoring behavior retained; evidence/calibration/independence boundaries unchanged.

## Implemented contract

InvalidModelEnvelope is an InvalidModelOutput/ValueError subclass with an allowlisted code and static message. Codes: object_required, message_required, content_required, completion_metadata, inference_metadata, invalid_json_or_budget. Missing/unusable string content retains raw_output=null; valid string content is separate from the message. Callers must not publish retained model content without review. Existing CLI publishes error class only; no raw private server error or diagnostic body is interpolated into its message.

The response must be an object with a message object and nonempty string content. When present, done must be an exact boolean; done_reason a string of at most64characters. Optional duration/token fields must be exact nonnegative integers<=2^63-1 (booleans rejected). Absent optional fields remain compatible with older saved/mocked responses. done=false or done_reason=length retains the existing generation-budget rejection. String content still needs strict JSON/finding-schema/source/location/guard validation; envelope validation is not entailment or an attack verdict.

Invalid outer JSON/budget raises owned rejection without retaining an arbitrary entire envelope. IO/HTTP/transport failures remain transport errors; no retry or successful fallback is invented. Cache hits use the same envelope/content checks. Invalid cache entries become misses and require fresh inference; validated responses only are written. Cache policy version4/envelope prevents old-policy keys being reused. No historical artifacts or vector collections are rewritten/certified.

Shared identity_from_models validates tags root/list/row/string types,<=256rows and name/digest strings1..512characters, then requires exactly one named match. Extra server metadata is allowed. Digests are opaque strings, not cryptographic attestation or proof of package/model integrity. Vector tags uses the same validation before PersistentClient construction. Embedding response must be an object containing embeddings, then retains prior row/dimension/finite/budget checks. These metadata failures are explicit ValueError, not chat-envelope diagnostics.
